# 需要解决的问题与改进点

这里区分已经实现的约束和后续需要实验验证的方向。优先顺序是补齐数据与评估、比较现成模型，再考虑融合特征和微调。

## P0 模型身份与索引一致性

**问题：** 两个模型即使都是 768 维，也可能位于不同向量空间。模型 revision、tokenizer 或预处理变化，也可能让新查询与旧图库不再对应。

**已实现：** 模型和 processor 固定到同一个 commit；索引保存完整身份指纹。查询前严格比较身份，同维度但 checkpoint 不同会报错。保存使用原子发布，默认不覆盖已有索引。

**继续验证：** 在未来依赖升级时，比较同一小批图片和文字的向量、Top-K 与数值误差；没有验证前不放宽身份检查。增加配置或 pooling 选项时提高处理版本并重建索引。

## P0 数据重复与评估泄漏

**问题：** 首次 10 个 runtime JPG 只有两种图片内容；后续新增一张后，11 张图仍只有三种内容。重复内容、同实物多视角和查询图自己入库，都可能使结果看起来过于理想。

**已实现：** 按 EXIF 归正、白底透明合成后的 RGB 像素哈希去重，保留 aliases；以图搜图默认排除相同像素的查询图。

**待解决：** 感知近重复、JPEG 重压缩和裁剪版本不能只靠精确哈希处理。为物理设备建立人工确认的组 ID；评估时按组划分，并明确是否允许同一实物的其他视角。

**验收：** 不把重复文件计入独立样本数；报告每种去重规则下的图库规模，以及错误过滤和漏过滤情况。[现有数据分析](data-assessment.md)

## P0 真实查询与相关性标签

**问题：** 当前没有独立的检索评估集，不能根据两张相似图片判断准确率。

**下一步：** 收集小规模真实图库和人工相关性标签，区分同类别、同型号、同实物检索。先看逐条 Top-K，再统计 Recall@1/5/10 和 MRR。多相关答案时应保留全部已确认正例。

**验收：** 固定查询、图库、标签和分区；每次模型或参数改变使用相同评估输入。不要使用模型自己生成的标签作为独立真值。

## P1 整图语义与细粒度区分

**问题：** 整图 embedding 容易反映“都是汽车”或“都是电气柜”的整体语义，可能忽略型号、接口、小缺陷与物体局部。

**候选实验：** 整图基线；主体框裁剪；整图与主体裁剪分数融合；具有空间位置的 patch 特征或局部重排。先测试已有预训练编码器，不立即训练新模型。

**验收：** 使用同类设备中的困难负例，比较各方案的排序、误匹配和耗时。单纯扩大普通类别差异不能证明细粒度能力。

## P1 OCR 与精确文字线索

**问题：** 铭牌、型号、序列号可能比外观更能区分具体设备，整图 embedding 未必保留精确字符。

**候选实验：** 文字 OCR 单独建立词项检索；视觉结果与 OCR 结果融合或重排。保留 OCR 原始文字、置信信息和人工校验，避免自动把 OCR 错误变成已确认型号。

**验收：** 固定包含近似型号、字母数字混淆和不可辨铭牌的查询集，分别报告外观检索、OCR 检索与融合结果。没有可辨文字时不推断精确 SKU。

## P1 纯文字长文档与多模态检索

**问题：** SigLIP 文本分支服务于图文对齐；默认模型的 64-token 输入也限制长文档。它不应直接替代一般长文档检索模型。

**已实现：** 超长查询明确报错，避免静默截断。

**候选实验：** 长文档使用专用文本 embedding 和文档分块，图片保持 SigLIP 空间，在结果层融合两种检索。不要直接比较两个不同模型空间的向量，也不默认拼接后就具有可比较的语义。

## P1 2D 到 3D 中的职责边界

**问题：** 图像语义相似不能证明三维几何、尺度、隐藏结构或部件组成正确。

**候选实验：** 将冻结视觉特征作为几何模型的条件，或用于检索参考视图。重建、相机、尺度与部件约束由相应模块负责。整图条件与 patch 条件分开验证。

**验收：** 使用独立几何或多视图依据评价重建，保持语义匹配分数与几何指标分开。未经确认的 GLB 运行产物不能直接当成真实三维监督。

## P1 预训练模型比较

**当前：** 已验证 SigLIP 2 Base 224；So400m 384 已提供选项，但没有本地效果结论。

**下一步：** 在固定评估集上比较冻结的 Base、So400m 和必要的分辨率/宽高比选项。记录实际峰值资源需求、加载、首次编码与常驻查询耗时。更大模型不自动等于设备检索效果更好。

## P2 规模与增量更新

**当前：** NumPy 精确搜索简单可核查；图片分批进入模型，但最终向量矩阵仍保存在内存中，扫描与哈希也有 I/O 成本。

**后续：** 大图库再加入向量内存映射、流式写入和 FAISS/HNSW 等 ANN。以模型指纹与图片哈希作为增量缓存键，正确处理文件修改、删除与移动。始终保留精确搜索对照，以衡量 ANN 的召回损失。

## P2 常驻服务与设备性能

**当前：** Python API 可复用已经加载的编码器；CLI 每次启动都重新加载模型。已在 M4 Pro / MPS 上运行，未在用户 RTX 5080 上验证。

**后续：** 有多次查询需求时先复用进程内 encoder，再按需要提供服务接口。分别测量下载、加载、首次编码、预热编码和端到端时间，不把纯模型时间当作用户总耗时。

## P2 有条件地微调

**已保留：** CLIP/SigLIP 损失及显式微调入口。本次没有执行训练。

**前提：** 先有人工核对的图文数据、按设备划分的留出集以及冻结模型基线。若性能不足，再比较只训练投影、参数高效微调或完整微调；训练过程关注假负例、重复设备和类别失衡。

**验收：** 留出检索集有可复现改进，并检查一般语义能力和跨设备表现是否退化；训练损失降低本身不构成效果结论。
