# OPUS-MT 领域术语约束与新查询评估

用户要求：给现有 OPUS-MT 增加逆变器、套管、散热片约束，检查接线和安装关系；继续不训练，用新增查询对比 Base / So400m 效果和端到端时间；把历史、当前及未来问题和改进持续保存并衔接。

## 决策与边界

本设计由实现者依据现有授权确定，不改变模型参数、现有查询或旧标签，不改写生成后的英文。比较三种解码：原始贪心 beam1、无约束 beam4、带源词触发词汇约束的 beam4；后两者共同参数一致，用于区分 beam 变化和约束作用。保留中文直接、自动英文、中英各0.5余弦融合。每次自动请求都真实翻译，不缓存英文；实际总时间含源词匹配、约束 token 编码、生成、解码、约束核验、SigLIP 编码与排序。加载/校验/首次请求另列。

领域规则只约束三个术语族：微型逆变器→microinverter(s)，逆变器→inverter(s)，变压器语境下的套管→bushing(s)，散热片→cooling fins 或 radiator fins。英文允许句首大写。中文最长匹配先处理微型逆变器，避免重复施加独立 inverter 约束；电缆套管等非变压器语境不强制 bushing。规则是源词触发的包含约束，不能保证词序、否定、可见性、接线或安装关系，因此上下文单独审阅。禁止看到测试结果后修改词表、beam、权重、译文或查询。

当前 Transformers 5.22.1 将 constrained beam search 移至 `transformers-community/constrained-beam-search`。仅下载并检查固定 revision `07b2f120b7db38f1d7bac617ad65ea130508f297` 的三个 Python 文件及 README，不下载该仓库附带的 Qwen 权重。在本机忽略目录保存并验证完整源文件哈希，作为本地 callable 使用；检索/翻译模型加载仍 `trust_remote_code=False`。不在仓库重新分发这个未列出仓库级许可的生成实现；保留其现有文件头/来源，记录集成限制。适配器、准备命令、哈希清单、测试均入库。约束结果缺少术语或未正常 EOS 结束必须明确失败，不能默默退回无约束或补词后冒充约束生成。

## 新查询

在词表/语义审阅规则固定后，由未看模型输出的独立助手根据原始图像、来源和描述编写16个新中文意图及配对英文、完整二元相关性标签。包含三种术语、接线、开闭壳、墙/柱安装、板下/背面、成排空间关系及不触发目标词的控制查询；只使用图中可见且来源支持的属性，不推断SKU。配对英文仅用于数据契约和参考，不输入翻译、不替换输出。新中文不得与历史8条相同；新查询集在任何新翻译或模型评分前冻结。

这是共享旧40图的新查询集，助手独立编写与复核，未经过独立人类审核，也不是新的现场图像留出集。需要如实标注这种独立性的范围。后续标签纠正或词表更新另建版本。

## 实现接口

- `src/siglip_tools/opus_constraints.py`：固定解码实现的准备/本地哈希加载，静态领域词表和源词识别，`OPUSConstraintTranslator(base, *, constrained=True, decoder_dir=...)` 包装现有 LocalTranslator，公开 identity/model_dir/device/translate；`constrained=False` 是无约束 beam4。两包装器可共享一个已冻结 OPUS 模型；不能修改 base 的生成设置或参数。提供逐请求约束/满足情况供保存，包含原样输出。
- `src/siglip_tools/term_benchmark.py`：每个检索模型一个独立进程，在同一常驻环境轮转7种策略：zh、original_en、original_fusion、beam_en、beam_fusion、constrained_en、constrained_fusion。每策略预热3次、16意图各10次，共1120热请求/模型、2240总样本。复用各自图像索引，测阶段及真实总时间，保存全部排序/逐次计时和失败。失败不能从分母排除，记录明确错误与耗时，效果计0并另列成功条件结果；如确无失败也应记录0。
- CLI 增加 OPUS 解码选择，默认 original；NLLB 不接受 OPUS 专用解码。新模块与实验不得破坏旧译者默认和历史可复现记录。
- `benchmarks/terminology-constraints-v1/`：词表、审阅规则、新查询/标签、原图库manifest的同字节副本、协议、freeze、译文、结果摘要、审计。原图/权重/外部生成代码/索引/逐次运行结果仅保存在忽略目录。
- `docs/issue-log.md`、`docs/README.md`、`docs/continuation.md`：可追踪问题编号、历史证据、状态、修复/验证和后续动作；AGENTS.md规定发现问题即登记、修复后补验证，交接时更新索引/接续文档，不能只留聊天。

## 验证与交付

先写失败测试，再实现匹配、token覆盖、无目标词、上下文歧义、失败关闭、上游 GenerationMixin callable 接口及配置不变性。真实模型预检只用历史开发查询，记录发现的问题与修改，不能用新测试查询选规则。冻结代码、词表、查询/标签、索引、权重、外部生成代码和协议，再顺序运行 Base / So400m。独立复算全部排序、计时分位数和约束/接线/安装关系审阅；保存负结果和不确定因果。全离线测试、lint、原始损失演示、构建、独立检出、私有仓库推送和CI验证后交付。
