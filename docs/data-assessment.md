## 现在就能做的验证

1. 使用两张原图建立两条记录的 embedding 索引，不把 runtime 重复上传的图片扩充为样本。
2. 用中英文描述检查文字查询能否返回 Top-K 排名和分数。
3. 用其中一张图做查询，排除自身后检查另一张图的返回情况。
4. 在复核的 runtime 11 张 JPG 上检查去重是否得到 3 条记录和 8 个重复别名，再用室内、户外描述检查三图排名。

原两张图都包含相似的设备与环境。“白色光伏逆变器”这类粗粒度描述可能对两张图都正确，因此它不能区分精确设备或证明 Top-1 能力。只有一张候选可返回的排除自身图片查询，也不能作为成功率统计。新增的第三张图增加了室内外差异，仍不足以推断一般检索质量。

## 建议补充什么

第一轮工程验证可以从 30–50 张图片、10–20 条人工核对的真实查询开始。这是便于快速发现问题的起步规模，不是统计充分性的保证，也不是训练数据量要求。

- 图片应覆盖不同物理设备和场景，不能主要靠重复上传、重压缩或裁剪来增加数量。
- 加入相似外观的干扰项，例如其他电气柜、控制箱、不同外形逆变器以及只有光伏板而没有目标设备的图片。
- 对每条查询，人工确认所有相关图片，而不是只凭文件名给一个答案。中英文查询可描述相同意图，用于比较语言表现。
- 区分“同类设备”“同一型号”“同一实物”这三种检索目标；不把它们混成一个标签。
- 多视角图片先按确认的物理设备分组。将来训练、调参、测试分区按设备分组，避免同一实物的不同视角泄漏。
- 需要型号检索时，补充可辨认铭牌、人工确认型号和 OCR 转写；单靠外观不建立精确 SKU 真值。

建议每张图记录：`image_id`、相对路径、来源、使用范围、`capture_id`、已确认才填写的 `physical_object_id`、人工类别。每条查询记录：`query_id`、查询内容、语言、相关 `image_id` 列表、相关性标准和分区。

## 是否需要训练

当前不需要。先运行冻结的预训练编码器，把图库、查询和相关性标签补齐，再比较预训练模型、整图与裁剪方案。训练备用入口已单独保留；两张图片不作为有效微调集或训练效果证明。
