## SIG-001：相同维度不保证模型与索引兼容

- **状态：已解决（有验证）；依赖升级复核持续保留。**
- **证据：** [设计](design.md)、[验证记录](validation.md)、[模型身份改进项](improvements.md#p0-模型身份与索引一致性)、[索引测试](../tests/test_index.py)、[编码器测试](../tests/test_encoder.py)。
- **影响：** 不同 checkpoint、processor、tokenizer 或预处理即使输出维度相同，也可能使新查询与旧图库处于不一致空间；仅检查向量长度会静默返回无意义排名。
- **实际处理与验证：** 模型和 processor 固定到同一 commit；索引携带完整身份指纹，查询严格比对。维度、数量、有限值、单位范数及持久化元数据有离线回归；两张原图索引保存重载后身份一致，改变 batch size 的向量在 `1e-5` 绝对误差内一致。
- **剩余行动：** 依赖、pooling、文本设置或处理实现变化时记录新身份/处理版本，先比较固定图文向量和 Top-K，再决定是否重建。Base/So400m 始终各用自己的索引，不绕过兼容检查。

## SIG-002：读取、编码、别名与索引发布可能来自不同输入

- **状态：已解决（有验证）。**
- **证据：** [进度中的独立审查](progress.md)、[验证记录](validation.md)、[输入变化回归](../tests/test_mutating_inputs.py)、[路径与持久化测试](../tests/test_index.py)；修复提交 `849b57e`。
- **影响：** 原图或重复别名在读取/编码期间变化，会使哈希与向量不再对应；Windows 盘符路径和 NUL 原先可被接受，违反安全相对路径约定。
- **实际处理与验证：** 从同一字节快照读取、解码和哈希，编码核对后的 RGB 快照；原子发布前复核全部原图及 aliases，变化即中止并保留旧索引。路径同时拒绝绝对路径、穿越、Windows 盘符和 NUL，默认不覆盖已有索引。独立审查先复现 7 个失败用例，再完成回归；随后真实 MPS 重建仍为 3 条内容、8 个别名，室内查询首位不变。
- **剩余行动：** 保留这些防护。原生 Windows 运行尚未因此得到验证；拒绝盘符/冒号样式文件名带来的可移植性取舍见原进度记录。直接构造低层 `ImageIndex` 时，调用者仍负责向量与记录的同批输入关系。

## SIG-003：文件数量、近重复与实物身份容易混淆

- **状态：已解决（精确重复与计数变更）；待验证（近重复与设备分组）。**
- **证据：** [数据检查](data-assessment.md)、[流程验证](validation.md)、[公开集去重检查](../benchmarks/equipment-v1/duplicate-review.json)。
- **影响：** 首次 runtime 10 张 JPG 只有 2 种内容；任务期间新增室内图后为 11 张、3 种内容、8 个副本。重编码格式、同照片裁剪、同一实物多视角与查询图本身都可能抬高表面效果；文件名也不能证明 SKU 或实物身份。
- **实际处理与验证：** 保留两次数据快照，确认数量变化来自新增文件。按 EXIF 归正、白底透明合成后的 RGB 像素去重并保留 aliases；以图搜图默认排除相同像素的查询图。公开 40 图集核对源哈希、像素哈希、64 位 dHash 和联系表，没有发现重复候选；这不是通用近重复自动合并功能。
- **剩余行动：** 人工确认 `physical_object_id`、来源与允许用途；对重压缩/裁剪评估漏检和误杀，按物理设备分组划分数据。原两图实物关系和再分发许可未确认，不能发布为已确认设备真值。

## SIG-004：可运行的 smoke test 与助手标签不能代替独立效果证据

- **状态：外部限制；人工审核与现场留出集待验证。**
- **证据：** [数据评估](data-assessment.md)、[设备报告](equipment-benchmark-v1.md)、[标注规则和纠正记录](../benchmarks/equipment-v1/annotation-notes.json)、[第二助手盲审](../benchmarks/equipment-v1/label-review.json)、[冻结记录](../benchmarks/equipment-v1/freeze.json)。
- **影响：** 两张原图/三种 runtime 内容没有检索标签，排除自身后只剩一个候选也不能统计成功率。后续 40 图/16 字符串只有 8 个中英意图，查询及相关性来自助手，未独立人类审核，公开图片的预训练重叠未知。Hit@5 已饱和也不表示正例找全。
- **实际处理与验证：** smoke test 只报告流程、原始排名与耗时；公开集在目标模型运行前冻结查询、图库、全部正例，保留第二助手盲审。指标分开记录 Hit@K、多正例 Recall@K、MRR 与完整排序 mAP，不把 16 个字符串当 16 个独立意图，也不把余弦分数当概率。
- **剩余行动：** 人工复核开门/裸露内部、套管/鳍片/百叶等标签边界，收集真实查询和按设备分组的现场留出集。纠正标签另建版本、重评两个模型，不覆盖 v1。微调仍以可靠数据、冻结基线和留出改进为前提，训练损失下降不能代替检索验证。

## SIG-013：已提供英文的融合收益不等于自动翻译收益

- **状态：已解决（有验证，口径与控制组）；策略泛化待验证。**
- **证据：** [固定双语实验](bilingual-fusion-v1.md)、[双语协议](../benchmarks/bilingual-fusion-v1/protocol.json)、[自动翻译对照](auto-translation-v1.md#与上一轮已提供英文对照)。
- **影响：** 双语实验使用助手预先编写英文；其 7–30 ms 检索耗时不含准备英文。融合也并非单调改善：Base i04/i07 AP 低于中文，So400m 英文 mAP 0.9578 高于融合 0.9420；总体 16 字符串平均不能与 8 意图融合行直接对比。
- **实际处理与验证：** 固定同模型两余弦各 0.5，保留中文、英文和融合三个控制组，不重新归一化均值向量、不按查询调权重。双语实验独立复算 48 份排序及 480 个计时，历史单语言排名全量一致；后来将真翻译另建实验、每请求重译并直接测总耗时，原双语报告保留。
- **剩余行动：** 在独立开发/留出集比较英文单独、固定融合和预先定义的选择规则。明确英文来源及其耗时；不把用更多查询信息的策略优势写成检索模型本身更强。

## SIG-015：生成配置的 None 会被模型默认回填，干扰长度与截断判断

- **状态：已解决（有验证）。**
- **证据：** [自动翻译验证](auto-translation-v1.md#复现与验证)、[冻结修正历史](../benchmarks/auto-translation-v1/freeze.json)、[上游回填回归](../tests/test_translation.py)；修复提交 `dd1f684`、`9e64487`。
