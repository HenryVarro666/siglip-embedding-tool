# 小规模设备检索评估计划

用户要求：收集来源明确、可用于测试的逆变器及相似设备图片，建立 30–50 图、10–20 条中英文查询的评估集，对比预训练 SigLIP 2 Base 与 So400m 的效果和耗时，不训练。

## 固定协议

- 目标为 40 张图片、16 条查询（8 个检索意图各有中文与英文版本）。允许在 30–50 图范围内根据来源和视觉审查调整图片数量，记录最终计数。
- 优先采用 Wikimedia Commons 的开放许可摄影作品。逐图保存文件页、原始 URL、下载 URL、作者、许可名称与 URL、页面 revision、源文件时间/哈希、本地下载哈希和修改说明。未知许可、缺少作者或不适合的文件不进入集合。
- 图库包含太阳能逆变器以及电气柜、变压器、UPS 等相似设备，加入没有逆变器的光伏场景作为背景干扰。具体构成以目视审查为准，不从文件名直接推定型号。
- 下载 Commons 的等比缩略版本以控制体积，记录尺寸与版本；不生成合成图片，不用裁剪/重压缩重复来增加独立样本数量。原图片、缩略图、权重、向量及原始运行数据保存在 Git 忽略的 data/、artifacts/ 与本机模型缓存。
- 图像元数据、许可/署名清单、查询和相关性标签可以随私有仓库保存，支持按来源重新获取图片。
- 在运行两个模型之前，逐张查看图像，标注可见设备类型、属性和可能的重复组，冻结查询与相关图片 ID。由助手目视标注，不声称已由独立人类标注员核验；标注局限在报告中说明。
- 不把 16 条双语查询当成 16 个独立意图。分别报告中英文结果及 8 组配对差异，保留每条查询的完整排序。用户可以用标注审查页面独立复核。
- 使用固定 checkpoint：Base `75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2`；So400m `e8e487298228002f3d8a82e0cd5c8ea9c567f57f`。同一环境、设备、float32 与图片 batch size；分别采用各自原生 224 和 384 输入，比较的是完整部署配置，不隔离容量与分辨率的影响。
- 计算 Hit@1/5/10、真正的多相关项 Recall@1/5/10、MRR 和完整排序 AP/mAP。Hit 与 Recall 分开，全部查询都必须有非空已核对正例，模型不得生成自己的真值。
- 下载时间不纳入推理时间。单独记录缓存权重加载、首次图片编码、图库批量编码、常驻文本查询与向量搜索耗时。测量前后同步加速器，记录预热和重复次数，模型分进程依次运行，避免内存/并发干扰。
- 在看排序之前冻结协议与标签；不据模型结果回改查询来提高分数。错误标签如需修订，应保留版本并对两个模型重新评估。

## 工作步骤

1. 收集候选文件与逐图许可元数据，下载审查版本。
2. 目视核对、精确/感知重复检查、确定最终清单和标签；生成本地可审查目录。
3. 用独立手算案例测试指标实现；实现可复现下载与评估入口。
4. 先冻结数据/查询/标签哈希，再依次运行两个预训练模型，保存模型身份、完整排名和计时样本。
5. 记录逐查询错误、中英文差异、相关项数量影响与小样本局限。更新模型选择和改进文档。
6. 运行测试、独立审查评估协议与实现、推送私有仓库；不上传原始图片和权重。
